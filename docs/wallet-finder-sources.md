# Wallet Finder evidence review

Manual review date: **2026-10-15**. The executable dataset is `src/lib/wallet-finder/evidence.ts`. It covers all 19 catalog entries, with separate records for each reviewed platform. This is a review of publisher documentation, release notes and distribution pages, not an installation, transaction, security audit or recommendation of a product's safety.

## Meaning of the fields

- `availability` means a public usable Zcash wallet channel is documented. A public beta is identified as beta. A download link alone does not prove a feature works.
- `shieldedSend` and `shieldedReceive` are separate. They establish a documented shielded workflow, not support for every shielded pool, migration path or address format.
- `hardwareSigning` means a dedicated device signs Zcash transactions, either through a software integration or on the listed hardware wallet itself. A second offline phone/computer is not automatically a dedicated hardware integration.
- `multichain` means holding/managing native assets on more than one blockchain. Swaps, CrossPay, bridges, multiple accounts and the capabilities of a host application do not suffice.
- `securityAudit` means a published independent security report about the named wallet product or its Zcash integration on the listed platform. It records the exact historic version or commit reviewed. It is not a finding that the current release is safe, complete, or audited. An audit of Zcash consensus, a shared SDK, a host wallet, or a hardware device alone does not automatically cover a companion wallet.
- `supported` needs an affirmative primary source for the scoped platform/channel. `unsupported` needs an explicit limitation or unavailable release. Missing, contradictory or unresolved evidence stays `unknown`.
- `checkedAt` records when the linked material was read. It is not the upstream publication date or an automatic freshness stamp. Unresearched capabilities have no date or sources. Reviewed uncertainties retain their source and review date.
- `desktop` is a UI grouping, not a claim of universal operating-system support. The scope names verified operating systems or explicitly retains the limitation.

Only requirements that are supported together on a single available platform can form a confident match. Unknowns must not be converted into false, or allowed to satisfy a requirement. Planned functionality is not a released capability.

## Maintenance

Recheck the particular platform, release channel, device model, firmware and companion before changing a capability. Include the exact supporting primary URL and a concise limitation. Rechecking a homepage must not refresh unrelated fields. A source moved/blocked or a contradiction should produce an explicit unknown until resolved. Changes to firmware, a network upgrade, app retirement, beta graduation or contradictory support documentation are reasons for a new field review.

This initial review intentionally does not infer unsupported hardware integrations or native multichain features from silence. A future reviewer can replace those unknowns with affirmative evidence. Do not fill them from the older catalog description alone.
